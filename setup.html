All study trackers

Publish once.
Study anywhere.

This guide is for hosting your personal trackers on free GitHub Pages and optionally syncing progress through your Google account. There is no server, build step or database.

1. Publish on GitHub Pages

  1. Create a public GitHub repository. Free GitHub Pages is available for public repositories; never upload credentials or private study data.
  2. Copy the contents of the coding folder into the repository root, including both tracker HTML files, index.html, setup.html, site.css, progress.js, config.js and .nojekyll. You can omit _build and tests.
  3. In the repository, open Settings > Pages. Choose Deploy from a branch, select your branch (usually main) and /(root), then Save.
  4. Wait for deployment, then open the published URL, usually https://USERNAME.github.io/REPOSITORY/. All links work under a repository subpath.

Export progress from the old site before moving. Browser storage belongs to an origin, so local preview progress will not automatically appear on GitHub Pages. Import the backup on the new site.

2. Enable optional Google Drive sync

Use the same OAuth client ID and Google account on every device. This uses Drive's hidden application data folder, not Google Cloud Storage or Firebase. Only application data permission is requested, not access to your personal Drive files. No client secret or service account is needed.

  1. In Google Cloud Console, create or choose a project. Enable Google Drive API under APIs & Services > Library.
  2. Open Google Auth Platform (or the OAuth consent screen). Fill in Branding with the app name and support email. Choose External audience for a personal Google account.
  3. While the app is in Testing, add your own Google account under Test users. Add https://www.googleapis.com/auth/drive.appdata in Data Access. Google classifies this scope as non-sensitive. Testing-mode consent can expire after seven days; reconnect when prompted. For broader use, move to Production and complete any requirements Google presents. Do not assume testing mode is a permanent public release.
  4. Create an OAuth client of type Web application. Add the exact JavaScript origin https://USERNAME.github.io, without the repository path. For local testing, separately add the actual origin, such as http://localhost:8765. A different port or hostname is a different origin. This popup token flow does not need a redirect URI.
  5. Copy the public OAuth client ID into config.js as googleClientId: "YOUR_ID.apps.googleusercontent.com", and publish the change. A browser client ID is public configuration; never add a client secret, token or service-account key.
  6. Open either tracker. Click Connect Google Drive. The first click loads Google sign-in; click again when prompted to open the popup, select your account and grant permission. Then click Sync now.
  7. On your other device, open the same site, connect the same account and click Sync now. Repeat for the other tracker; each tracker syncs separately.

These small Drive API requests normally need no paid storage product or billing account, but are subject to Google's account storage limits, API quotas and policies. GitHub Pages only serves the static files.

Daily use and conflict handling

  • Changes save locally immediately. Sync is manual, not continuous: sync before switching devices and after opening the tracker on another device.
  • Sync merges item changes; the most recent timestamp wins for the same item. Unmarking an item also syncs. Keep device clocks accurate. Exactly equal timestamps resolve deterministically by status number.
  • Each browser keeps its own Drive snapshot, avoiding one device overwriting another's whole progress. Concurrent syncs may need another sync on each device to converge. Browser storage clearing creates a new device snapshot; older snapshots remain in Drive app data.
  • Use a current browser with Web Locks support over HTTPS or localhost for Drive sync. Local saving and JSON backups do not require Google sign-in. Clearing browser data, private browsing or storage eviction can remove local progress.
  • Access tokens stay in memory, not in browser storage or your repository. Reloading or token expiry requires reconnecting. Disconnect clears the in-memory connection, not local or Drive data.
  • Connecting a different Google account merges this browser's existing progress into that account when you sync. Use separate browser profiles for separate people or accounts.

Back up and recover

Click Export progress to download a versioned JSON backup. Import progress validates the tracker and file, then merges newer changes; it does not replace everything or roll back newer edits. Python and DSA backups are not interchangeable. Keep a backup before switching sites or accounts. Existing browser progress from the original tracker is migrated automatically on the same origin.

When something goes wrong

  • Google Drive is not configured: add the client ID to config.js and redeploy.
  • Origin or access denied: check the OAuth JavaScript origin, test-user list and requested app-data permission. Allow popups and Google sign-in scripts.
  • Expired access or HTTP errors: reconnect and retry. Your local changes remain available. Offline use saves locally, but syncing requires a connection.
  • Local saving failed: export immediately before closing the page. Check browser storage permissions and space. Do not rely on cloud sync until local storage is working.
  • Remove cloud data: manage the app in Google Drive Settings > Manage apps and delete its hidden application data. To revoke access, use your Google account's third-party connections settings. Revoking access is separate from deleting progress.

Maintaining the trackers

The shared layout source is _build/template.html. Both generated trackers must use that template and load the sibling config.js and progress.js. Keep the existing item IDs and storage keys when updating study content. Run the dependency-free JavaScript tests with node --test tests/progress.test.cjs.
