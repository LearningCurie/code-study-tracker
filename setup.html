Setup and security

The trackers are static pages. There is no server and no database. Progress lives in your browser, in backup files you export, and, if you sign in, in a private app folder in your own Google Drive.

Security and privacy

Signing in with Google gives this site one narrow permission: drive.appdata. That is a hidden folder in your Drive that only this app can see. The table shows what that allows.

The site canCreate, read, update and delete its own progress files in the hidden app folder, and read your email address so the account menu shows which account is signed in.
The site cannotSee, open, change or delete any of your Drive files, Gmail, Photos, Contacts, Calendar, passwords or account settings. Google enforces this; the code cannot ask for more without showing you a new consent screen.
Where the sign-in token goesIt is sent only to Google's Drive API. So one sign-in covers every page and tab, the token is kept in this site's browser storage until it expires (within an hour) or you sign out, whichever comes first. It is never written to a file, a backup or the repository, and it can only reach the hidden app folder.
Who else can see your progressNobody. There is no server to send it to. Other visitors have their own browser storage and their own Google accounts.
What Google sees without sign-inEvery page loads fonts and Google's sign-in library from Google's servers, so the sign-in pop-up opens on the first click. That shares your IP address with Google like any embedded Google resource, but no progress and no account data.

Why open source does not expose your Google account

  • The client ID in config.js is public by design. It is not a password. Google only accepts sign-ins from the web addresses listed for it, so a copy of this code on another site cannot use it.
  • Visitors only ever sign in to their own accounts. If someone else signs in on your site, they grant access to their own app folder, not yours.
  • There are no secrets to steal. The site needs no client secret, API key, service account or password, and the repository contains none. GitHub secret scanning and push protection are on for the repository.
  • Nobody can change the live site without your GitHub account. Pull requests only take effect if you merge them.

Protections built into the pages

  • A strict Content Security Policy allows scripts only from this site and Google's sign-in library, and network requests only to Google's Drive API.
  • No inline scripts; study data is stored as inert JSON. Anything read from storage or imported files is shown as plain text, never as HTML.
  • Pages refuse to render inside another site's frame, which blocks click-jacking.
  • Imported and synced files are validated (format, tracker, size and number of entries) before they are merged.
  • All external links open in a new tab with rel="noopener".

You can remove the site's access at any time from your Google account's third-party connections. Your progress in the browser is not affected.

Syncing between devices

  1. On any page, click Sign in with Google in the top right. Choose your account and allow the app-folder permission.
  2. Every tracker syncs straight away. While you are signed in, each change syncs again a moment later, and Sync now syncs every tracker at once.
  3. On your other device, open the same site and sign in with the same account. Progress for every tracker merges in.
  • One sign-in covers every page and tab of the site in this browser. It lasts about an hour; after that, click Sign in with Google again. Next time it usually takes one click.
  • New trackers sync automatically. Sync finds every tracker saved in the browser or in Drive, including ones you have not opened on this device yet.
  • If the same item changed on two devices, the most recent change wins. Unmarking an item also syncs. Keep device clocks accurate.
  • Each browser writes one file of its own, so two devices never overwrite each other's files. Files from older versions of the site are read and merged, and this browser's old files are removed once their progress is safely in its new file.
  • If you leave a page before a change has synced, the next page you open while signed in syncs it.
  • Sign out on this device signs out every page and tab in this browser. It does not delete progress here or in Drive.

Backups

Open the Backup menu on any page to export or import progress. One backup file holds every tracker. Importing merges changes, newest first; it never wipes newer progress. Backups from older versions, which held one tracker each, still import. Export before clearing browser data, switching browsers or moving the site to a new address, because browser storage belongs to one web address.

Publish your own copy

  1. Fork or copy the repository. Free GitHub Pages works with public repositories; never commit credentials.
  2. Open Settings > Pages, choose Deploy from a branch, pick main and / (root), then save.
  3. Your site appears at https://USERNAME.github.io/REPOSITORY/. Every link works under that path.

Turn on Google sign-in

This is only needed for your own copy. The trackers work without it; the sign-in button explains that sync is not configured.

  1. In Google Cloud Console, create a project and enable the Google Drive API (APIs & Services > Library).
  2. Open Google Auth Platform. Under Branding, enter the app name and support email. Choose External audience.
  3. Under Data Access, add only https://www.googleapis.com/auth/drive.appdata. Do not add other scopes.
  4. Under Audience, leave the app in Testing and add your own Google account as a test user. Only listed test users can sign in. Testing-mode sign-ins may ask you to approve again after seven days.
  5. Under Clients, create an OAuth client of type Web application. Add the exact JavaScript origin, for example https://learningcurie.github.io (no path, no trailing slash). Leave redirect URIs empty; this sign-in uses a pop-up.
  6. Put the client ID in config.js as googleClientId: "...apps.googleusercontent.com" and publish. Never add the client secret.

For local testing, add http://localhost:PORT as a separate origin and remove it when you are done. A different port or host name is a different origin.

Owner security checklist

Google Cloud

  • Authorized JavaScript origins list only your Pages address (plus localhost while developing). Redirect URIs are empty.
  • The only scope is drive.appdata. Only the Google Drive API is enabled.
  • No API keys or service accounts exist in the project. The client secret has never been copied anywhere.
  • Keep the app in Testing with only your account, unless you want other people to sign in. If you publish it to Production, they still only reach their own app folders.

GitHub

  • Two-factor authentication is on for your GitHub and Google accounts.
  • Secret scanning and push protection stay on. Consider a branch rule on main that blocks force pushes and deletion.
  • Review any pull request that touches progress.js, config.js or the Content Security Policy with extra care. That code decides what the page asks Google for.

Troubleshooting

  • "Sign-in is not configured": add the client ID to config.js and publish.
  • Pop-up blocked or closes immediately: allow pop-ups for this site, then click Sign in with Google again.
  • "Access blocked" or "origin mismatch" from Google: check the JavaScript origin in the OAuth client and that your account is a test user.
  • "Session expired": sign in again. Changes made meanwhile are saved in the browser and sync after you sign in.
  • "Local saving failed": export a backup immediately, then check browser storage settings and free space.
  • Remove cloud data: in Google Drive, open Settings > Manage apps, find the app and delete its hidden data.

Maintaining the trackers

The trackers are generated from _build/template.html with shared site.css, tracker.css, tracker.js and progress.js. Keep item IDs and storage keys stable when you change study content, so saved progress still matches. Run the tests with node --test tests/progress.test.cjs.

Sign-in, sync and backup are shared by the whole site, so adding a page never changes how they work:

  • A new tracker built from the template only needs a new storageKey (lowercase letters, digits and hyphens). It joins the shared sign-in, Sync now and backups automatically.
  • Any other new page gets the same account controls by copying the app bar and loading ./config.js then ./progress.js at the end of the body. Copy the Content Security Policy from an existing page so Google sign-in is allowed.
