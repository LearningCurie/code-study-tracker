# Audit of the old DSA page

Audited page: `dsa.html` as committed at `9a568c9` (`git show HEAD:dsa.html`), the problem tracker generated by
`_build/build_dsa.py`. The work-in-progress rebuild in the working tree was ignored. Checks ran on 1 November 2026.

## Summary

- **What the page is.** A problem tracker, not a guide. It has a 6-step "How to use it" list, a 15-link Study kit and
  34 topics. Each topic gives 2 to 4 "Spot it" cues, 3 or 4 "Core moves" and one line of Python tools (a median of 71 words
  of teaching text per topic, 2,409 words across all 34), then 1 to 5 Read links, 3 to 5 Watch links and the problems:
  **899 trackable items** (795 free LeetCode problems split Easy 148 / Medium 472 / Hard 175,
  plus 104 on other judges: CSES 69, HackerRank 25, AtCoder 10).
- **Links.** 3,249 link instances (3,184 unique URLs). Every one was put in exactly one class:

  | Class | Links | Share |
  |---|---:|---:|
  | Specific and useful | 2,704 | 83.2% |
  | Generic | 485 | 14.9% |
  | Long video (over 20 minutes, no timestamp) | 59 | 1.8% |
  | Dead | 1 | under 0.1% |
  | Video, length unverifiable | 0 | 0% |

- **Problem rows are healthy; the teaching layer is not.** All 795 LeetCode problems are free and resolve, all 515 NeetCode
  practice pages exist, all 795 doocs solution pages and all 104 other-judge pages answer HTTP 200. The weak spots are:
  433 problems (54%) get a YouTube *search page* instead of a video, 28 linked problem videos run over 20 minutes, and at
  topic level only 158 of 230 Read and Watch links (69%) point at something specific that answers the topic; the other 72 are
  playlists (17), whole Wikipedia articles (9 of 9), textbook chapters, home pages, mislabelled pages, long videos (29)
  and the one dead link.
- **One dead link**: cp-algorithms' longest increasing subsequence page (dpstr) is now a stub saying the article has moved.
- **The core problem** is that the page outsources all teaching. A learner who opens "Dynamic programming: 1D" gets eight
  bullet points and then a 5 hour 10 minute course, a 57-minute lecture, a 10-hour playlist and a 60-page PDF chapter. No
  topic has a worked trace, a template, a correctness argument, a hint, or a check-yourself question.
- **Coverage gaps** against the new plan: no foundations or workflow module, no standard-library internals, no primers or
  hint ladders, nothing on DSA in production systems or AI systems, no frontier results, no projects or capstone, and no
  review queue. Missing techniques include binary lifting, meet in the middle and divide and conquer as a named strategy.
- **Must be preserved**: storage key `dsa-status` (saved as `dsa-status:v1`), all 899 item ids exactly as they are
  (LeetCode numbers as strings, `cses:N`, `ac:dp_x`, `hr:slug`), status numbers 1 Solved / 2 Brute only / 3 Stuck, the
  Easy / Medium / Hard split, the legacy `{a, b, c}` import, and the Drive sync contract in `progress.js`.

## 1. Method

- **Source.** The JSON in `<script type="application/json" id="tracker-data">` of the committed page was parsed and every
  string under a key `h` beginning with `http` was collected, keeping its role (kit, topic Read, topic Watch, problem
  title, or a chip on a problem row). The scripts live in the session folder (`files/audit/`), not in the repository.
- **YouTube videos (419 unique ids).** `www.youtube.com` refuses the TLS handshake from this machine, but the same watch page
  is served by `m.youtube.com` to a mobile browser User-Agent. For every id the page was fetched, `"lengthSeconds"` was read
  from `videoDetails`, the returned `videoId` was checked against the requested one, and `playabilityStatus` was read. All
  419 returned `OK` with a matching id, so every length was measured; the fallback class "video, length unverifiable" is
  empty. Lengths are in `_build/data/yt_durations.json` as `{"VIDEOID": seconds}`. A noembed spot check of two videos returned the
  same titles. Requests ran 3 at a time with a 0.4 to 1.0 second pause.
- **Long means over 20:00 (1,200 seconds)** with no `t=` timestamp in the link (no link has one). This is applied strictly;
  of the 53 long videos, 27 are between 20 and 25 minutes, so a looser reading of "about 20 minutes" would move those to
  specific. The borderline topic-level ones are:
  NeetCode walkthrough: Trapping Rain Water (23:21), Abdul Bari: merge sort (20:23), Reducible: 5 simple steps for any recursive problem (21:02), NeetCode walkthrough: Word Search II (20:54), William Fiset: Dijkstra's algorithm (24:46), Reducible: 5 simple steps for solving DP problems (21:27), Abdul Bari: longest common subsequence (23:35), NeetCode walkthrough: Edit Distance (21:00), NeetCode walkthrough: Burst Balloons (21:20), William Fiset: sparse table (23:18).
- **YouTube playlists (18) and search pages (433)** are generic by rule. Playlist size or total running time was read from
  the playlist page header for the reason column.
- **LeetCode.** Slugs and `paid_only` flags from `_build/data/lc_all.json` (4,087 problems, cached 21 October 2026). Each
  slug was also checked to map back to the item's number and its difficulty to match the group it sits in. No mismatches.
- **NeetCode practice pages** against `_build/data/nc_slugs.txt` (1,093 slugs). The live `neetcode.io/sitemap.xml` was also
  fetched today; it has the same 1,093 slugs and contains all 515 used. (neetcode.io answers 200 for any path, so HTTP
  status alone proves nothing there.)
- **doocs.** Every one of the 795 pages was fetched (more than the 150 sample asked for), in random order, 2 at a time with a
  0.6 to 1.2 second pause. A missing doocs page returns a real 404 (checked with a made-up number). All 795 returned 200,
  every page contains the problem title (785 drops the question mark) and a Python solution.
- **CSES, AtCoder, HackerRank.** All 104 problem pages and the three landing pages were fetched; each host returns a real
  404 for a missing task (checked). All returned 200 and every page title matches the item title on the old page.
- **Everything else** (the 95 Read URLs and 7 kit pages, 102 URLs) was fetched with a desktop browser User-Agent; anchors were checked in the
  page; word counts and section headings were used to judge whether the page answers the item. Two hosts refuse scripts:
  `leetcode.com/problemset/` answers 403 (it loads in a browser, and the earlier link check lists it as verified by hand)
  and `graphics.stanford.edu` refuses connections from this machine (the Wayback Machine holds HTTP 200 snapshots from
  October 2026). Neither is counted as dead.
- **Classes.** *Specific and useful*: a page or short video that answers the item without hunting (problem pages, solution
  pages, a focused article, a deep link, a video of 20 minutes or less). *Generic*: home page, roadmap, problem list,
  repository root, playlist, search results, or a whole long article where only a section answers the item; this class
  also takes pages that do not answer the item at all (off-topic or mislabelled). *Long video*: over 20 minutes, no
  timestamp. *Dead*: HTTP error, missing or moved page, or a paid-only LeetCode problem. Topic-level links are judged
  against that topic's cues and core moves, so four URLs get different classes in different topics (the Tech Interview
  Handbook arrays, strings and DP pages, and VisuAlgo's BST page).
- The previous report `_build/data/urls_dsa.report.json` (21 October) listed 3,184 URLs and 0 broken. It checked existence
  only (oEmbed for YouTube), which is why it missed the moved cp-algorithms page and could not see length or relevance.

## 4. The core problem: resources that do not answer the item

The old page's model is "read one article, watch one video, then write the core moves from memory". That only works if the
links teach the move named on the page. Too often they do not:

1. **Whole courses and lectures as "watch one video".** Dynamic programming 1D links freeCodeCamp's 5:10:02 DP course, a
   57:18 MIT 6.006 lecture and a 10-hour take U forward playlist; none has a timestamp for "say the state in words" or
   "derive the recurrence from the last decision". Graphs links a 2:12:18 course, binary trees a 1:48:53 course, linked
   lists a 1:27:23 course. The Study kit's "courses to keep open" are 8:03:17 and 6:44:39 long.
2. **A lecture for one line.** Bit manipulation's core move "x & (x - 1) clears the lowest set bit" is paired with MIT
   6.172's 78:54 "Bit Hacks" lecture (performance engineering in C). Data structure design links the 80:55 MIT 6.046
   skip-list lecture for a single problem (1206). Strings links a 61:00 MIT recitation for rolling hashes that it shares
   with amortised analysis.
3. **Playlists (17 at topic level, 1 in the kit).** Eight take U forward playlists (3 to 10 hours each, or 13 videos for
   greedy), three Aditya Verma and three NeetCode playlists, Tushar Roy's 4-hour DP list, all 26 hours of MIT 6.042J
   for "Math, number theory and geometry", and William Fiset's 55-video data structures playlist labelled "segment
   trees".
4. **Whole Wikipedia articles (9 of 9 are generic).** "Prefix sum" is mostly about parallel scan algorithms (about 6,800
   words); "Finite-state machine" is automata theory with nothing on DP over states; "Sweep line algorithm" is about
   segment intersection, not the +1/-1 event counting the interval problems use; "Cache replacement policies" surveys
   dozens of policies when 146 and 460 need LRU and LFU; "Binary search tree", "Trie", "Longest common subsequence" and
   "Levenshtein distance" each answer the item in one section of a long article.
5. **Textbook chapters.** Jeff Erickson's backtracking, DP and greedy chapters (roughly 26, 60 and 28 PDF pages) are the Read
   link for topics whose learn text is eight bullet points.
6. **Mislabelled or off-topic pages.** "Tech Interview Handbook: strings (window techniques)" under Sliding window never
   mentions sliding windows. The Tech Interview Handbook DP page is the Read link for state-machine DP and has nothing on
   it. The recursion page under Recursion and backtracking never mentions backtracking. VisuAlgo's BST and AVL visualiser
   is the Read link for general binary trees. cp-algorithms' Aho-Corasick page sits under Tries although no core move or
   problem uses it. "MIT 6.006: DP part 2" under grid DP covers LCS, LIS and coins, not grids. The state-machine topic's
   walkthrough of 121 teaches the sliding-window solution, not a state machine.
7. **Home pages and docs roots.** The kit's USACO Guide, cp-algorithms and Erickson links are home pages; the BST topic
   links the sortedcontainers documentation home rather than the SortedList page; the arrays topic links the whole
   `collections` reference (about 8,500 words) instead of the Counter and defaultdict sections (the design topic does deep
   link to OrderedDict, which shows the better pattern).
8. **Single-problem walkthroughs posing as topic teaching.** 57 of the 128 Watch links are NeetCode walkthroughs of one
   problem, and every one of them is already the Video chip on that problem's row. They teach a problem, not the pattern.
9. **Search pages instead of help.** 433 of 795 problems (54%) link a YouTube search for "leetcode N title explained". In
   range queries 10 of 10 problems have no video, only a search link; in DP over intervals, trees, bitmasks and digits
   15 of 20.

## 6. What must be preserved

| Contract | Detail |
|---|---|
| Storage key | `storageKey: "dsa-status"`. `progress.js` saves `localStorage["dsa-status:v1"]` as `{"version": 1, "tracker": "dsa-status", "entries": {id: {"status": n, "updatedAt": ms}}}`. The key must match `^[a-z0-9][a-z0-9-]{0,62}$`. `tracks.js` (home page card) is keyed by it too, and `study-last:dsa-status` remembers the last opened topic. |
| Legacy import | If `dsa-status:v1` is absent, the original tracker's `localStorage["dsa-status"]` (`{a: [...], b: [...], c: [...]}`) is imported as a = 1, b = 2, c = 3 with `updatedAt` 0. Keep this path. |
| Item ids | All 899, byte for byte: 795 LeetCode numbers as strings (`"1"`, `"217"`), 69 `cses:N`, 10 `ac:dp_x`, 25 `hr:slug` (Appendix C). The new page must pass every old id to `StudyProgress.mount({ids})`: `set()` rejects ids not in that list, so an id dropped from the page keeps its stored status but can no longer be changed. Unknown ids already in storage are kept, never deleted. |
| Status numbers | 0 not started (a cleared status is stored as 0 with a timestamp so the clear wins merges), 1 Solved, 2 Brute only, 3 Stuck. Clicking the active status sets 0. New labels (for example "With help" and "Redo") may change wording but not the numbers or their order of meaning. |
| Difficulty split | Easy / Medium / Hard from LeetCode's own label in `lc_all.json`, used for grouping and the difficulty filter. Other-judge items have no difficulty and sit in their own group. |
| Drive sync | Unchanged `progress.js` contract: one file per browser in the Drive `appDataFolder`, named `study-progress-<deviceId>.json` with appProperty `studyProgress = "2"`, holding `{"version": 2, "trackers": {"dsa-status": entries, ...}}`. Sync reads every file, merges per item (newer `updatedAt` wins, ties go to the higher status), writes to every tracker in local storage, then uploads only this browser's file; older per-tracker files (appProperty `studyTracker`) are read and then deleted. A Web Lock serialises syncs; changes mark the store dirty and trigger a delayed sync when auto sync is on. Export and import of a JSON backup use the same merge. Limits: 20,000 entries, ids up to 120 characters. |
